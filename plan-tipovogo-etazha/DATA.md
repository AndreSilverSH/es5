# DATA.md — схема данных плана типового этажа

Вся презентация **полностью управляется данными**: один JSON-объект `FLOOR_DATA` описывает
геометрию, квартиры, помещения, проёмы, мебель, инженерные маркеры и текст листа.
Ни один размер не зашит в код отрисовки.

## 1. Три способа подставить свои данные

| Способ | Где | Когда удобен |
|---|---|---|
| **JSON-редактор в презентации** | вкладка «Данные» → textarea → «Применить» | быстро попробовать правки, не трогая файлы |
| **Импорт/экспорт файла** | кнопки «Скачать JSON» / «Загрузить JSON» там же | передать коллеге, версионировать |
| **Файл `js/data.js`** | заменить объект `FLOOR_DATA` | финальная интеграция в репозиторий |

Экспортированный из презентации JSON полностью эквивалентен `FLOOR_DATA` и принимается обратно.
Объект также доступен в консоли: `window.FLOOR_DATA`, применить программно — `window.APP.setData(obj)`.

> Данные не обязаны быть полными: `normalize()` (js/app.js) дополняет отсутствующие блоки
> значениями по умолчанию, пересчитывает габариты этажа по крайним помещениям и сам создаёт
> карточки квартир по списку помещений. Минимум для работы — непустой массив `rooms`.

## 2. Система координат

* Единицы — **метры**, начало координат — левый верхний угол габарита этажа, ось **Y направлена вниз**.
* Помещение задаётся либо прямоугольником `rect: [x, y, w, h]`, либо произвольным контуром
  `poly: [[x,y], …]` (по часовой или против — не важно).
* Стены не рисуются отдельными элементами: наружная стена — полоса `wall.facade` внутрь от контура,
  межквартирные/ядра — `wall.party`, перегородки — обводка помещений `wall.partition`.
  Поэтому комнаты достаточно стыковать «впритык»: толщина стен учтена правилами отрисовки.
* Проёмы привязываются отрезком `seg: [[x1,y1],[x2,y2]]` **по оси стены**; отрисовка сама стирает
  стену под проёмом и ставит условное обозначение (окно/дверь/лифт).

## 3. Верхний уровень объекта

```jsonc
{
  "meta":     { … },        // тексты листа и штампа
  "building": { … },        // этажность, высоты, конструктив
  "wall":     { "facade": 0.4, "party": 0.4, "partition": 0.2 },
  "size":     { "W": 24, "D": 15.6 },          // можно не указывать — вычислится
  "axes":     { "x": [ … ], "y": [ … ] },      // оси: { id, at }
  "zones":    { … },        // словарь зон: name, color, fill
  "apartments":[ … ],
  "rooms":    [ … ],        // обязательный блок
  "balconies":[ … ],
  "openings": [ … ],
  "stairs":   [ … ],
  "lifts":    [ … ],
  "risers":   [ … ],
  "furniture":[ … ],
  "notes":    [ "…", "…" ]  // нумерованный список примечаний на листе
}
```

### meta
`project, object, address, corp, stage, sheet, drawing, scale, level, floorNote, author, checker, date` —
строки; идут в шапку, футер, штамп и заголовок браузера.

### building
`floorsAbove` (этажей), `floorHeight` (высота этажа, м), `clearHeight` (в свету, м),
`sections`, `type` (описание конструктива строкой). Используются в аксонометрии, объёмной схеме и фактах.

### zones
Ключ зоны → `{ name, color, fill }`: `color` — акцент (обводки, диаграммы), `fill` — заливка пола.
Стандартные ключи: `living, kitchen, wet, storage, circ, core, common, service, outdoor`.
Свои ключи добавлять можно — помещения ссылаются по имени зоны.

## 4. Помещения (`rooms`) — главный блок

```jsonc
{
  "id": "a1-bedroom1",        // уникальный идентификатор
  "apt": "a1",                // квартира: id из apartments или "core" для общих помещений
  "name": "Спальня",          // подпись на плане
  "zone": "living",           // ключ из zones
  "rect": [0.4, 0.4, 4.2, 4.0],   // ИЛИ "poly": [[x,y], …]
  "note": "мастер-спальня",   // необязательно: третья строка подписи (при площади ≥ 10 м²)
  "labelAt": [2.5, 2.4]       // необязательно: точка подписи вместо центра bbox
}
```

Правила, которые стоит соблюдать (их же проверяет QA-контур):
* помещения одной квартиры не пересекаются и не наезжают на другие квартиры;
* сумма помещений + стены должна заполнять габарит без «дыр» (иначе на плане будут белые пятна);
* жилые комнаты ≥ 8 м², коридоры ≥ 1,0 м по ширине, марши лестниц ≥ 1,2 м — нормативные подсказки.

### balconies
Та же структура, что и `rooms` (`id, apt, name, rect|poly`), но попадают в слой летних помещений:
пунктирная плита, стеклянное ограждение, подпись с площадью поверх стен.

## 5. Проёмы (`openings`)

```jsonc
{ "kind": "window", "seg": [[1.2, 0], [3.0, 0]], "apt": "a1" },
{ "kind": "door",   "seg": [[8.4, 8.9], [8.4, 9.8]], "apt": "a1", "w": 0.9, "hinge": "auto" },
{ "kind": "lift",   "seg": [[11.4, 3.2], [13.3, 3.2]] },
{ "kind": "opening","seg": [[6.0, 8.4], [6.9, 8.4]] }   // проход без полотна (арка)
```

* `kind`: `window | door | lift | opening`.
* `seg` лежит **на оси стены**; толщина стены берётся по функции `wallThickness` (наружная/межквартирная/перегородка).
* У дверей полотно и четверть рисуются по короткой стороне; направление открывания определяется автоматически.

## 6. Лестницы, лифты, стояки, мебель

```jsonc
"stairs": [{ "rect": [8.6, 0.4, 2.6, 5.6],
            "flights":  [{ "x": 8.6, "y": 0.4, "w": 1.2, "h": 4.3, "treads": 11, "dir": "up" }, { … "dir": "down" }],
            "landings": [[8.6, 4.7, 2.6, 1.3]] }],
"lifts":  [{ "rect": [11.4, 0.4, 1.9, 2.8], "cap": 630, "label": "Л1" }],
"risers": [{ "x": 7.4, "y": 5.0, "r": 0.22, "label": "В1-Т3-К1", "kind": "water" }],
"furniture": [{ "room": "a1-bedroom1", "kind": "bed-double", "at": [2.5, 1.6], "rot": 0 }]
```

* `stairs.flights[].dir` — `up`/`down` (направление стрелки); `treads` — число ступеней в марше.
* `risers[].kind` — `water | smoke | elec | tech` (цвет маркера); маркер автоматически ставится
  в нижний левый угол помещения, в котором лежит точка, код подписывается только у широких помещений.
* `furniture[].kind` — из словаря условных обозначений: `bed-double, bed-single, sofa, table-dining,
  table-desk, wardrobe, kitchen-line, kitchen-corner, sink, wc, bath, shower, washer, stove, fridge,
  chair-round` и т. п. (см. `layerFurniture` в js/render-plan.js). `at` — центр предмета, `rot` — градусы.

## 7. Квартиры (`apartments`)

```jsonc
{ "id": "a1", "no": 1, "title": "Квартира 1", "kind": "3-комнатная евро" }
```

`id` связывает помещения (`rooms[].apt`), цвет берётся из палитры `APT_COLOR`
(a1 синий, a2 охристый, a3 зелёный, a4 пурпурный; следующие id — из расширения палитры).
Площади, комнатность, бирки и диаграммы считаются автоматически по геометрии помещений
(летние помещения — с понижающими коэффициентами 0,5/0,3).

## 8. Оси, размеры, примечания

* `axes.x / axes.y`: `[{ "id": "А", "at": 0 }, { "id": "Б", "at": 4.2 }, …]` — марки и пузыри.
* `dims` (необязательно): позиции размерных цепочек и марок осей; по умолчанию расставляются снаружи контура.
* `notes`: массив строк — нумеруются автоматически и попадают в блок «Примечания» на листе.

## 9. Что проверяет QA-контур (`tools/qa` в этой же папке)

`node tools/qa/check.js` прогоняет весь pipeline без браузера и валит сборку (exit code 1), если:
помещения пересекаются или оставляют непокрытые зоны; проём не лежит на оси стены; мебель вне комнаты;
марш уже 1,2 м; жилая комната меньше 8 м²; в SVG появились нечисловые атрибуты (`NaN`, «склейки» строк);
XML некорректен; диаграммы не строятся. `node tools/qa/render.js` (после
`npm i --prefix tools/qa @resvg/resvg-js`) даёт контрольный растр всех видов в `tools/qa/png/`.

## 10. Мини-пример (достаточный минимум)

```jsonc
{
  "rooms": [
    { "id": "r1", "apt": "a1", "name": "Комната",  "zone": "living",  "rect": [0.4, 0.4, 5.0, 4.0] },
    { "id": "r2", "apt": "a1", "name": "Кухня",    "zone": "kitchen", "rect": [0.4, 4.6, 3.0, 3.0] },
    { "id": "r3", "apt": "a1", "name": "Прихожая", "zone": "circ",    "rect": [3.6, 4.6, 1.8, 3.0] }
  ],
  "openings": [
    { "kind": "window", "seg": [[1.2, 0], [3.4, 0]], "apt": "a1" },
    { "kind": "door",   "seg": [[4.0, 7.6], [4.9, 7.6]], "apt": "a1" }
  ]
}
```

Этого достаточно: габарит, контур стен, заливки, подписи с площадями, бирка квартиры,
диаграммы и аксонометрия пересчитаются сами. Остальные блоки добавляются по мере необходимости.
